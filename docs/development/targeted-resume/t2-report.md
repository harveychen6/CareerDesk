# T2 implementation report

## Interfaces

- `createMaterial({ content, projectId?, createProject?, title?, stage? })` saves immutable source text (1–20,000 UTF-16 characters), computes SHA-256 on the server, and returns the source row. New project creation requires `createProject: true`, a nonblank user title and an explicit `stage: 'planned' | 'active' | 'done'`; no project is created otherwise. Project and source creation share a transaction.
- `listMaterials(projectId?)` returns source rows plus `facts` (each with exact `sourceText`). `extractMaterial(id, extractor?)` returns the same enriched material. Existing candidates are returned before calling a provider, preserving edits and preventing repeated paid calls. Injected `MaterialExtractor` is `(content: string) => Promise<Array<{ text: string; start: number; end: number; sourceText: string }>>`; every result is checked against original text. The fake provider splits actual source text.
- `updateMaterialFacts(id, expectedRevision, facts)` accepts `{ id, status: 'candidate' | 'confirmed' | 'rejected', text?, stage?: 'planned' | 'active' | 'done' | 'unknown' }[]`. `expectedRevision` is a positive safe integer and applies to each submitted fact; UI updates one fact at a time. Unknown/cross-material IDs and stale revisions fail atomically. Text is trimmed, source offsets/content never changed.
- `listConfirmedFacts()` returns only explicit confirmed facts. Each has DB fields `id`, `materialId`, `projectId`, `text`, `sourceStart`, `sourceEnd`, `status`, `stage`, `revision`, `createdAt`; plus `sourceRef: { materialId: string, start: number, end: number, contentHash: string }`, exact `sourceText: string`, and `project: ReturnType<typeof getProject>` (object or null). At read time hash, range, excerpt and material/project ownership are checked. Stage `unknown` must be treated only as non-outcome pending clarification; project `active` may contain `done` subfacts. The database fields have inferred string types; consumers should validate stage if they need a discriminated union.
- `GET /api/materials?projectId=`, `POST /api/materials`, `POST /api/materials/:id/extract`, `PATCH /api/materials/:id/facts`, and `GET /api/materials/confirmed` wrap these functions. The patch validates revision as a JSON number, not a cast. Stale revisions return 409; unconfigured extraction returns 503 without deleting saved material.
- `runStructuredTask<T>(prompt: string, schema: z.ZodType<T>): Promise<T>` in `src/server/ai/structured.ts` sends one JSON request with a 60-second timeout and validates the result; it does not retry or log response/secrets. Task-specific fake handling belongs in adapters. `segmentMaterial(content)` uses host-owned UTF-16 offsets, line boundaries and bounded chunks; the model selects IDs and the server maps them to source text/ranges. Candidate output is capped at 100 per extraction. Model selection can omit material; confirmation does not prove objective truth or semantic support.
- Named `MaterialIntake({ projectId?: string, onChanged?: () => void })` in `src/components/projects/MaterialIntake.tsx` fetches materials and projects, allows project selection/new title with explicit stage (default active), paste/save, explicit existing `factsMarkdown` import as new source, extraction, editable candidates with source excerpts/stage, and confirm/reject. Local candidate drafts survive list refreshes. Strings are in separate `materialsCopy` in `src/content/zh-CN.ts`. No workspace wiring is included.

## Verification and limits

- Added `tests/materials.test.ts`, using temporary real SQLite and fake/injected providers: hashes and UTF-16 range checks, explicit confirmation, cross-material/unknown IDs, conflicts, failed extraction/source retention, unconfigured provider HTTP 503, revision validation, repeated extraction preserving edits without a provider call, host segmentation, explicit new project creation, and long unbroken Unicode source.
- Red evidence: repeat extraction test failed with `unexpected call` before the early return; long source test failed with invalid reference before bounded segmentation. Initial absent-module tests failed on import before implementation.
- `npm test`: 14 files, 38 tests passed before the final long-source case; `npm test -- tests/materials.test.ts` passed 8 tests after it. `npm run typecheck` passed after the final segmentation change. Vitest emits its existing Vite CJS deprecation warning. Tests were run with normal escalated permissions due to sandbox realpath EPERM; no real model was called and no secrets were printed.
- No commits or pushes. No visual/browser test or integration wiring; parent T5 owns those.


## Project-context review fix

`MaterialIntake` now keys its inner view by `projectId`. Switching projects remounts the view and initializes its selection from the new ID; unsaved input in the prior project is discarded. A disposed view ignores late refresh results and does not call `onChanged`, while a sequence guard prevents an earlier refresh overwriting a newer one in the same context. Already-started server actions may finish for their original project. `tests/material-intake.test.ts` checks key separation and async scope invalidation; no browser interaction test was run. After this fix, `npm test -- tests/material-intake.test.ts tests/materials.test.ts` passed 10 tests and `npm run typecheck` passed.
