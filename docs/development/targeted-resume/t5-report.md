# T5 岗位定制简历界面交接

## 使用路径

1. 在「岗位」添加岗位并保存完整 JD。保存岗位与模型任务独立。岗位列表按最近更新顺序展示，可以展开修改已保存的 JD。
2. 在「选择确认事实」复用可用事实，或展开「粘贴、导入或补充材料」，选择已有经历或新建经历。保存原文后整理候选，核对出处和阶段，再逐条确认。项目抽屉也可整理该项目的材料。
3. 点击「分析完整 JD」，查看职责、必要条件、优先条件、背景条件、原文、证据和最多三项可选补问。可通过材料补充回答，也可明确标记没有相关经历。变更所选事实或确认项后需要显式重新分析。
4. 选择一页或两页，点击「生成改写建议」。进入「简历」查看每条建议的原句、岗位要求、事实出处、理由和风险，逐条接受或排除。确认级风险必须勾选核对项，阻止级风险无法接受。离线分析和建议显示「离线演示结果」。可以跳过模型任务，通过「创建空白岗位稿」手工编辑。
5. 点击纸面项目描述直接编辑，失焦后保存。岗位稿档案编辑当前冻结的个人信息，经历母版档案编辑全局信息。自动保存串行携带当前修订，冲突时本地改动仍显示，点击「读取最新修订并重试」保留被编辑的内容并重试。
6. 工作稿保存后可导出 Markdown 或打开打印页。点击「保存已投快照」冻结修订，历史条目提供日期和两种导出。此操作只创建本地记录。纸面估算超出所选页高时显示提示，最终分页由打印预览核对。

## 改动

- `JobsWorkspace.tsx` 接入 JD、确认事实、分析、生成、任务取消和岗位稿入口。分析与生成使用可取消请求，切换岗位隔离请求和未保存的原始材料输入。
- `MaterialIntake.tsx` 和 `Board.tsx` 接入项目上下文、原文折叠和提取取消。保留原有项目上下文隔离，读请求随上下文取消。
- `ResumeWorkspace.tsx`、`TailoringReview.tsx` 和 `resume-save-queue.ts` 接入建议审阅、待保存预览、修订冲突重试、档案和快照。当前稿与历史导出 URL 都带指定修订号，母版继续读取当前全局数据。
- `ResumeSheet.tsx`、纸面样式、打印页及 Markdown 导出展示简介和项目阶段。进行中项目仍可显示已完成的子事实，计划中项目手工加入后显示「尚未执行」。
- `zh-CN.ts` 集中新增文案并更新侧栏岗位稿计数标签。手工创建岗位稿的 HTTP 入口使用空白容器。

## 最终审阅修复

1. **清空正文。** 岗位稿纸面和修订接口将空文本保存为无描述，历史迁移和母版仍沿用各自的原始显示规则。
2. **保留逐句出处。** 手改时逐条匹配原来完全相同的可见句子，一条旧句最多匹配一次。新增或修改的句子标为手工未映射，并从当前句子重新汇总出处。回归覆盖接受两条建议后改一条、重复一条、保存快照和导出。
3. **保留未保存输入。** 工作区侧栏及返回岗位等站内链接在有未保存编辑时询问是否离开，取消后停在当前页。JD、档案和原始材料输入也受保护。打印、新标签页、下载和同页锚点保持原操作。
4. **手工加入后建项目。** 工作稿详情单独列出素材库新增项目，用户勾选后才写入当前修订。已有项目和历史稿保持冻结内容。
5. **提示原文超长。** 新建及编辑 JD、粘贴材料的输入框保存完整粘贴文本并显示计数。超出 12000 或 20000 字符后禁用保存，接口也返回 413。
6. **迁移前备份。** 已有库发现待执行迁移时，在创建或修改表前通过 SQLite `VACUUM INTO` 生成一致的副本，成功后保存在 `DATA_DIR/backups`。回归验证有 WAL 内容的旧库副本、备份失败时原库未变、新库和已升级库跳过备份。

侧栏完整度计入至少有一条有效确认事实且没有待确认候选的项目，旧素材仍沿用原统计。开始编辑工作稿时会清除上次保存投递快照的提示。
